# Этап 1. Острова и переход на лодке

## Критерии готовности (записаны до реализации, 2026-11-23)

Автотест (`tools/test_coop.sh`, сервер `-coopautotest -coopdebug`, клиент A
`-coopautotest`, клиент B `-coopbot`, сервер + 2 клиента по сети):

1. Кампания стартует на `Centre`: у сервера 4 лодки (N/S/E/W) и каменный круг.
2. Предложение вдали от лодки — отказ, перехода нет.
3. Предложение у лодки, когда напарник кровоточит, — отказ всем с причиной.
   (То же для голода и смерти — тот же код `TravelBlocker`.)
4. Предложение у лодки — запрос напарнику; отказ напарника — отмена.
5. Согласие напарника → переход обоих: `Centre → North` (первое посещение,
   генерация), у каждого игрока — спавн у лодки прибытия (< 10 м).
6. `North`: одна лодка (`South`, обратно на `Centre`); игра не падает без
   каменного круга (нет `NullReferenceException` из `ReDropTeleportParts` и
   RPC камней).
7. `North → Centre`: повторное посещение — сервер **загружает** остров без
   генерации; опустошённый на `Centre` сундук пуст; опустошённый тайник
   фрагмента пуст; спавн у северной лодки.
8. `Centre → East` — второе первое посещение, спавн у лодки.
9. В логах сервера и клиентов нет `TypeLoadException`, нет новых исключений от
   кода мода; клиенты пишут `TEST client: spawned on <остров>` с правильным
   островом.

Проверка руками (игроки), когда будет время: подсказка у лодки на экране,
клавиши B / N, сообщения в чате.

## Решения ведущего по ходу этапа

- **Клавиши**: `B` — предложить отплыть / согласиться, `N` — отказаться. В игре
  свободны (`C_SaveManager.SetDefaultKeyBinds`: E/Q — наклон, F —
  взаимодействие, Y — показать себя, T — чат, O — торг).
- **Второй игрок соглашается откуда угодно**: «у лодки» должен быть только
  предлагающий (радиус 12 м). Плывут все заспавненные игроки.
- **Один игрок на сервере** (напарник отключился) — плывёт сразу, без запроса.
- **Каменный круг всегда активен** уже с этапа 1 (`EnableStonesActivationTimer
  = false` в `ConfigureGamePlayForNewMap`) — решение игроков из дизайна; заодно
  снимает падение `RequestTargetInventoryContent` без круга.
- **Клиент всегда генерирует остров сам** (как в игре), сервер — только при
  первом посещении. Состояние острова (лут, тайники) — только на сервере, клиенты
  получают его штатно (содержимое сундуков — по запросу, пустые тайники — в
  bootstrap).
- Тайники фрагментов: файл `TeleCaches.xml` игры не перезаписываем (в MP
  `ReturnAliveCaches` дал бы дубли), опустевшие — свой список по позиции.

## Не входит в этап (дальше)

- Вещи игроков при переходе (этап 2) — сейчас после перехода стартовый набор.
- Счёт фрагментов при переходе обнуляется игрой (этап 3).
- Предметы, лежащие на земле, трупы — не переносятся и не сохраняются.
